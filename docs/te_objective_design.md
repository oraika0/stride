# Objective function 設計問題：avg LU 不可作為 RL 優化目標，MLU 才是主目標

## 1. Avg LU 不是有效的優化目標

直覺上可能認為：好的路由策略應該讓所有鏈路的平均利用率（avg LU）更高（充分利用網路）或更低（保留餘量）。但 avg LU 與路由品質之間**沒有直接關係**。

### 反例：avg LU 提升，MLU 反而惡化

在相同 TM 下比較兩種 routing 策略。拓撲沿用 [`directed_vs_undirected_metrics.md`](directed_vs_undirected_metrics.md) 第 2 節的 4 節點範例，所有邊容量 = 1 Mbps。

- **方案一：直連路徑**（A→B、C→D）
- **方案二：繞路**（A→D→C→B、C→B→A→D）

![image](https://hackmd.io/_uploads/BkQM7Pi3Wl.png)

### 比較

| | 方案一（直連） | 方案二（繞路） |
|---|---|---|
| MLU | **0.5** | 1.0 |
| avg LU | 0.125 | **0.375** |
| 實際品質 | 健康、無壅塞 | C→B 滿載 |

方案二的 avg LU 是方案一的 3 倍，但路由品質顯著更差。

### 為什麼 avg LU 不能作為目標

**最大化 avg LU** 會鼓勵 agent 選擇更長的路徑 — 每條流量經過更多 hop，自然會「用到」更多邊，avg LU 上升。**但這只代表 agent 傾向繞路，不代表繞出來的路徑合理**。

**最小化 avg LU** 同樣有問題 — 它會鼓勵 agent 把流量集中在最短路徑上（用最少的邊），但忽略了這些短路徑上的邊可能已經壅塞。

根本原因：**avg LU 反映的是「網路整體被使用了多少」，而非「負載分配得好不好」**。

- avg LU 的高低主要由路徑長度決定，而非由負載平衡程度決定
- 因此**單看 avg LU 的數值無法判斷路由品質好壞** — 同一個 avg LU 可能對應到「路徑稍長但負載均勻」的健康策略，也可能對應到「路徑稍長但依然出現瓶頸」的壞策略（如前述方案二）。必須搭配 MLU 一起看才能區分

### 正確的優化層次

| 優先級 | 目標 | 指標 | 意義 |
|---|---|---|---|
| **第一** | 最小化最大方向利用率 | MLU (directed) | 消除瓶頸（全局硬約束） |
| **第二** | 在 MLU 相同的方案中，再最小化次大利用率或 avg LU | 2nd-MLU / avg LU | 避免不必要的繞路（tiebreaker） |

**結論：**
1. **MLU 是硬約束：一條邊壅塞就會丟封包，不管其他邊多空閒。avg LU 是軟偏好：在瓶頸被消除的前提下，傾向選擇不浪費頻寬的路徑。**
2. **avg LU 可以作為 tiebreaker，但不應作為主要目標。**
