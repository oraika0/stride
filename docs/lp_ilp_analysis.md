# LP / ILP / SP Optimal MLU Analysis

Date: 2026-03-26 (updated: 2026-04-14)

## Setup
- LP: flow splitting allowed (K-path restricted), K=20
- ILP: single-path only (no flow splitting), K=4 (前 4 條 = k_paths.json 的前 4 條)
- SP: shortest path (OSPF), each OD pair uses the first path in k_paths (no optimization)
- Directed MLU (each direction counted separately)
- ILP solver: scipy.optimize.milp (HiGHS)

**Observations**

- LP mean 0.8340 is substantially higher than the 20-TM subset (0.6723) because the per-hour set spans **all hours of the day** including evening peaks, not just the daytime hours represented in the legacy 20-TM list.
- **~25.5 % of hourly TMs are LP-infeasible** (even flow-splitting can't route them below 100% MLU). These correspond to congested evening peaks where total demand exceeds network capacity; they must be either down-sampled via `tm_scale` or excluded from training.
- 3 TMs are pathological outliers (MLU > 5.0, including TM-1238 @ 38.47 — likely a bad XML or extreme burst). Recommend filtering `tm_list_train` to exclude TMs with LP MLU > 1.5 to avoid polluting training with un-routable demands.
- p99 = 1.46 (vs. max = 38.47): the heavy tail is very thin, so a simple `lp_mlu ≤ 1.5` filter removes the 15 worst and keeps 99.4 % of the data.
- ILP was not solved for all 2644 TMs (solve time would be days on a single node). For the 20-TM subset LP-ILP gap is near-zero (§Geant 20-TM), so the LP values here are a good proxy for the optimality lower bound of any single-path policy.
- `baseline_mlu_by_tm.json` is consumed by `train_loader.py` (`tms_infeasible_count` with `feasibility_tolerance=0.15`) so the training eval correctly computes per-TM feasibility against the per-hour LP baseline.

### Observations

**跨 topology 共通結論**：
- **TE 優化的必要性**：即使 LP 最佳 MLU < 0.86，SP routing 直接讓 MLU 飆到 >1.0（壅塞）
- **LP-ILP gap 多數 ≈ 0**：Geant/24tm 幾乎全為 0；144tm 多數 <1% 但有 32 個 TM gap >1%（最大 11.5%）。Single-path routing 通常接近 LP optimal，少數 demand pattern 需要 flow splitting

**Geant**：
- Mixed capacity (1.55~100 Mbps) 造成 TM-00 有 5.4% LP-ILP gap（瓶頸邊 13→14 需要 flow splitting 分散壓力）
- SP-LP gap 變化大（11%~52%），因為不同 TM 對窄邊的壓力不同

**32-node 24tm vs 144tm**：
- 24tm 本質上只有一個 demand pattern（等比例縮放），SP-LP gap 恆定 114.2%，bottleneck 永遠在 1→3
- 144tm 有真正的 demand diversity：SP-LP gap 從 61% 到 181% 大幅變化，bottleneck 在 16 條不同 link 間轉移
- 144tm 對 DRL 訓練更有價值 — agent 需要學會應對不同的 demand pattern 和不同的 bottleneck 位置
- 144tm 的 LP MLU 更寬 (0.41~0.86)，比 24tm (0.50~0.75) 有更多難度層次
- 144tm 的 LP-ILP gap 比 24tm 大：32 個 TM gap >1%（vs 24tm 全為 0），表示 uniform capacity 下部分 demand pattern 仍受益於 flow splitting，但均值僅 0.8%
